# DOCX / PDF → Markdown

Локальное приложение Windows для преобразования **DOCX и PDF** в Markdown, который удобно хранить и читать на GitHub. Текст берётся из структуры документа или текстового слоя PDF, изображения сохраняются отдельными файлами. **OCR не используется:** надписи внутри картинки не распознаются и не заменяют само изображение.

## Запуск на Windows

1. Скачайте / обновите проект.
2. **Дважды нажмите [start.bat](start.bat).** Откроется окно выбора DOCX или PDF.
3. Укажите исходный файл и, при желании, существующую папку для результата. Нажмите «Конвертировать».

На первом запуске `start.bat` проверяет Python 3.11+, при его отсутствии пытается установить Python 3.13 через `winget`, затем создаёт `.venv`. Скрипт не скачивает повторно подходящие библиотеки: для DOCX нужны `python-docx` и `lxml`, для PDF — `pypdfium2` и `Pillow`. Если PDF-библиотеки временно не удалось скачать, DOCX остаётся доступным, а при выборе PDF приложение подскажет повторить установку через `start.bat`. Для медленного PyPI таймаут — 60 секунд; альтернативный индекс задаётся переменной `PIP_INDEX_URL`.

Исходный документ не меняется. Для `method.docx` **или** `method.pdf` создаётся `method_md/` рядом с ним либо в выбранном каталоге. При повторном запуске появится `method_md_2/`, затем `_3/`: существующие папки не перезаписываются.

## Контекстное меню Windows (необязательно)

**Дважды нажмите [install-context-menu.bat](install-context-menu.bat).** Пункт «Конвертировать DOCX/PDF в Markdown» появится при правом клике и по `.docx`, и по `.pdf`: «Показать дополнительные параметры» → команда конвертации. Приложение запустится только после выбора пункта, сохранит результат рядом с исходником, покажет результат или ошибку и завершится. **Никакого фонового приложения нет.** Для выбора другой выходной папки откройте обычное окно `start.bat`.

Регистрация действует только для текущего пользователя Windows, не требует администратора и не меняет программы для открытия DOCX/PDF. Для удаления дважды нажмите [uninstall-context-menu.bat](uninstall-context-menu.bat). Если перенесли папку проекта, повторно запустите установщик пункта меню: Windows хранит путь к `start.bat` на момент установки.

## Командная строка (по желанию)

`start.bat` без аргументов открывает GUI. С файлом DOCX или PDF доступен прямой запуск:

```bat
start.bat "C:\Docs\method.docx"
start.bat "C:\Docs\method.pdf" --output-parent "C:\Exports"
start.bat "C:\Docs\method.pdf" --output "C:\Exports\custom-folder"
```

`--output-parent` — существующая родительская папка; `--output` — точный путь к новой папке. Одновременно их использовать нельзя. Для ручной установки Python 3.11+ с Tkinter: `py -3 -m pip install -e .`, затем `py -3 -m doc_to_md_converter`.

## Что будет на выходе

```text
method.pdf                  (или method.docx)
method_md/
├── index.md
├── assets/
│   ├── images/
│   │   ├── image1.jpeg
│   │   └── image2.png
│   └── pages/              (только для страниц исключительно с векторной графикой)
│       └── page1.png
└── conversion.log
```

**Ссылки относительные**, например `![Изображение 1](assets/images/image1.jpeg)`. На GitHub загрузите **всю папку** `method_md/` вместе с `assets/`; локальные пути вида `C:\Users\...` в ссылках не используются. Предупреждения записываются в `conversion.log`. Папка `assets/pages/` создаётся только для страниц PDF, на которых есть векторное содержимое, но не удалось извлечь ни текст, ни отдельные изображения. Пустые страницы и обычные страницы PDF не дублируются.

## DOCX: особенности и ограничения

Поддерживаются основные абзацы, заголовки, таблицы, списки, выделения, ссылки и изображения. Вложенные медиафайлы DOCX копируются **побайтно в исходном формате**, без OCR и изменения изображения. Повторно использованные ресурсы не дублируются. Сноски, комментарии, колонтитулы и OLE-ресурсы переносятся в отдельные разделы или файлы; сложная вёрстка и формулы могут отличаться от исходника, о чём сообщается в логе.

## PDF: особенности и ограничения

PDF — формат фиксированной вёрстки без надёжной семантической структуры заголовков, абзацев и таблиц. Конвертер извлекает доступный **текстовый слой** и изображения приблизительно в порядке их расположения, разделяет результат по страницам и сохраняет повторно используемые изображения один раз. JPEG / JPEG2000 по возможности извлекаются **без перекодирования**; некоторые способы хранения изображения требуют формирования PNG. Извлечённые изображения остаются файлами, а не текстовыми описаниями. **Полностраничные PNG не создаются**, если на странице извлекается текст или хотя бы одно отдельное изображение. Исключение — страницы исключительно с векторной графикой без извлекаемого текста/изображений: для них формируется визуальная копия в `assets/pages/`, иначе содержимое целиком потерялось бы. На смешанных страницах не переносимые векторные элементы отмечаются в `conversion.log`, но вся страница не дублируется. Пустые страницы не рендерятся.

**Сканированный PDF без текстового слоя не станет редактируемым текстом:** OCR намеренно не выполняется, но изображения сканов сохраняются. Колонки, переносы, ссылки, таблицы, маски прозрачности и форматирование PDF могут передаваться неточно — проверяйте по исходнику или визуальной копии. PDF с паролем без ключа не поддерживается. Обработка выполняется локально, документы не отправляются в облако.

PDF-обработчик использует [pypdfium2](https://pypdfium2.readthedocs.io/) (Apache-2.0 / BSD-3-Clause) и Pillow.

## Тесты

```bat
py -3 -m pip install -e ".[dev]"
py -3 -m pytest -q
```

CI на Windows проверяет DOCX, PDF, изображения, сканы без OCR, векторные объекты, выбор выходной папки, регистрацию и удаление обеих команд контекстного меню. Также тестируются два запуска `start.bat` без скачивания зависимостей. **Настоящие методички DOCX/PDF пока не предоставлены:** регрессионная проверка на них остаётся открытой.
