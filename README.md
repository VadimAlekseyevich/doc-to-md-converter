# DOCX → Markdown

Локальный конвертер методичек из DOCX в Markdown с извлечением **оригинальных изображений**. Никакого OCR: надписи внутри картинок остаются внутри картинок. Выходную папку можно целиком положить в Git, а `index.md` просматривать на GitHub.

## Запуск на Windows

**Дважды нажмите `start.bat` в корневой папке проекта.** Ничего вводить в терминале не нужно.

При первом запуске файл проверяет наличие Python 3.11+, при необходимости пытается установить Python 3.13 через Windows Package Manager (`winget`), создаёт локальное окружение `.venv` и запускает приложение прямо из исходников. Подходящие уже установленные библиотеки используются повторно; скачиваются только отсутствующие или несовместимые `python-docx` и `lxml`. Отдельно загружать `setuptools`/`wheel` для запуска больше не требуется. Если `winget` недоступен, скрипт подскажет, где установить Python вручную.

Если `pypi.org` отвечает медленно, установщик использует увеличенный таймаут (60 секунд) и повторные попытки. Если доступ к PyPI заблокирован сетью, скачивание действительно необходимых библиотек невозможно: проверьте VPN/прокси или настройте доступный индекс пакетов через `PIP_INDEX_URL`. Повторно создавать папку `.venv` или переустанавливать Python не нужно — просто повторите запуск.

В приложении можно выбрать DOCX и **папку для сохранения результата**; если её не указывать, результат появится рядом с исходным файлом. Старые результаты не перезаписываются.

## Контекстное меню Windows (по желанию)

В корне проекта **двойным кликом запустите `install-context-menu.bat`**. Команда «Конвертировать DOCX в Markdown» появится только у **файлов `.docx`** в меню Проводника: правая кнопка по документу → «Показать дополнительные параметры» → наша команда. После нажатия `start.bat` запускает конвертацию выбранного документа и показывает короткое окно с итоговым путём или ошибкой; затем процесс завершается. Постоянно работающего фонового приложения нет. Результат создаётся рядом с исходным DOCX и не перезаписывает предыдущие экспорты. Чтобы выбрать нестандартную папку, откройте обычное окно приложения через `start.bat`.

Регистрация происходит **только для текущего пользователя**, без прав администратора; ассоциация Word по умолчанию не меняется. Для полного удаления пункта меню дважды запустите `uninstall-context-menu.bat`. Перед переносом/удалением папки проекта удалите пункт меню или после переноса запустите установщик повторно: Windows хранит путь к `start.bat` на момент установки.

## Относительные пути изображений

Markdown создаётся в виде `![UseCase\\_AS\\_IS.jpg](assets/images/image2.jpeg)`: **в круглых скобках уже относительная ссылка**, которая продолжит работать на GitHub, если загрузить всю папку экспорта вместе с `assets/images`. В квадратных скобках теперь остаётся лишь безопасное короткое имя картинки либо текстовое описание, а не полный путь `C:\\Users\\...` из свойств Word. Оригинальный файл изображения при этом не переименовывается по исходному частному пути, не преобразуется и не распознаётся через OCR.

Для запуска через командную строку, если понадобится:

```bat
start.bat "C:\Docs\method.docx" --output-parent "C:\Exports"
```

## Ручная установка и запуск

Если автоматическая установка не подходит, требуется Python 3.11+ с Tkinter.

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m doc_to_md_converter
```

В окне укажите DOCX, при необходимости выберите место сохранения, нажмите **Конвертировать** и прочитайте лог. Также доступен запуск через командную строку:

```bash
python -m doc_to_md_converter "path/to/method.docx"
# При необходимости задайте ещё не существующую папку явно:
python -m doc_to_md_converter "path/to/method.docx" --output "path/to/export"
# Существующая родительская папка для auto-named экспорта:
python -m doc_to_md_converter "path/to/method.docx" --output-parent "path/to/exports"
```

Результат по умолчанию создаётся рядом с DOCX. Уже существующая папка **не перезаписывается**: создастся `method_md_2`, затем `_3` и т. д.

```text
method.docx
method_md/
├── index.md
├── assets/
│   └── images/
│       ├── image1.png
│       └── image2.jpeg
└── conversion.log
```

`index.md` использует относительные ссылки `assets/images/...`; не отделяйте его от `assets/`. Изображения копируются из ZIP-пакета DOCX побайтно, без OCR и конвертации; повторно используемые файлы не дублируются. Встроенные медиафайлы, не упомянутые в отображаемом содержимом, тоже сохраняются, перечисляются в разделе «Дополнительные изображения» и отмечаются в логе.

## Что поддерживается в MVP

Заголовки, абзацы, базовое выделение, списки, ссылки, таблицы, inline/anchored изображения и изображения в таблицах. Содержимое колонтитулов добавляется в конце документа отдельным разделом. Картинки извлекаются и через OOXML `drawing`, и через старый VML `pict`.

Markdown не способен точно передать сложную верстку Word. Текстовые блоки (text box), сноски, концевые сноски и комментарии выгружаются в основной документ/дополнительные разделы; точная вёрстка и якоря исходного DOCX могут отличаться. Вложенные OLE-файлы сохраняются побайтно в `assets/objects/` со ссылками из Markdown; их содержимое не конвертируется. Формулы Word дают предупреждение и текстовое представление без математической вёрстки. Диаграммы без встроенного изображения, слияния ячеек, вложенные таблицы и некоторые другие элементы сопровождаются предупреждениями вместо незаметного пропуска. EMF/WMF сохраняются без преобразования, но GitHub может не показать их предпросмотр; для них нужен отдельный этап генерации превью. Отслеживаемые изменения: добавленный текст сохраняется, удалённый пропускается; перед конвертацией лучше принять/отклонить изменения Word.

## Тесты

```bash
python -m pip install -e '.[dev]'
pytest -q
```

Тесты создают временные DOCX и проверяют текст, порядок блоков, изображения, относительные ссылки, выбор каталога назначения, сохранение заметок/комментариев/OLE и защиту от перезаписи. GitHub Actions запускает тесты на Windows и проверяет `start.bat` повторно при `PIP_NO_INDEX=1`, чтобы исключить ненужные загрузки при повторном запуске. **Настоящие методички ещё не предоставлены**: проверка на них остаётся открытой задачей.
