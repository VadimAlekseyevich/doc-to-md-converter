# Roadmap: DOCX / PDF → Markdown

## Цель

Конвертировать методички из `.docx` и `.pdf` в читаемый на GitHub Markdown с текстом и отдельными изображениями. OCR не используется: текст берём из структуры DOCX или доступного текстового слоя PDF, картинки не заменяем текстовым распознаванием. Изображения DOCX сохраняем побайтно; PDF извлекаем без перекодирования там, где позволяет формат, иначе в PNG.

## Стек

- **Python 3.11+**
- **python-docx + lxml + zipfile** — разбор DOCX.
- **pypdfium2 + Pillow** — извлечение текста/картинок из PDF и визуальные копии только для векторных страниц без извлекаемого текста и изображений.
- **Tkinter** — минимальный desktop GUI без отдельного фронтенда.
- **pytest** — проверка конвертации на тестовых документах.

## Структура результата (MVP)

Рядом с `method.docx` или `method.pdf` создаётся папка `method_md/`:

```text
method.docx (или method.pdf)
method_md/
├── index.md
├── assets/
│   ├── images/
│   │   ├── image1.png
│   │   └── image2.jpeg
│   └── pages/ (только для векторных страниц без извлекаемого текста/картинок)
│       └── page1.png
└── conversion.log
```

`index.md` ссылается на ресурсы **относительными путями**; всю папку `method_md/` можно загрузить в Git без исходного DOCX/PDF. В первой версии — один Markdown-файл на документ; разбиение на несколько файлов по главам можно добавить позже.

## Критерии готовности MVP

- Текст DOCX или текстовый слой PDF находится в Markdown, а изображения представлены **самими файлами**, без OCR и без подмены текстовым описанием.
- Все извлекаемые изображения сохранены, ссылки на них открываются в GitHub; ничего неподдерживаемого не теряется без предупреждения.
- Результат создаётся рядом с исходником либо в выбранном каталоге, GUI и контекстное меню показывают итог и ошибки для DOCX/PDF.
